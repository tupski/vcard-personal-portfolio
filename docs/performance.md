# Performance & deployment notes (Phase 9)

The application optimizes what it controls. A few things belong to the web
server or the host, and are documented here rather than hard-coded into
Laravel, so the same codebase stays portable across shared hosting, cPanel,
aaPanel, VPS and Docker.

## Application-side (already implemented, no configuration needed)

| Concern | Where | Notes |
|---|---|---|
| Public content cache | `app/Support/ContentCache.php` | Cached between requests, invalidated automatically on any admin save/delete. Uses `CACHE_STORE` (`database` by default, `file` works too). Disable with `CONTENT_CACHE=false`. |
| Conditional requests | `app/Http/Middleware/CachePublicResponse.php` | Sends `ETag` on public HTML/XML/text; a repeat visit with `If-None-Match` gets `304` and no body. Admin and auth routes are excluded. |
| Static asset caching | `public/.htaccess` | Fingerprinted `build/` files get `immutable`; un-hashed `assets/` get a week + revalidation. Guarded by `IfModule mod_headers.c`. |
| Query reduction | `app/Models/Setting.php`, `ContentRepository` | All settings load in one query; blog detail resolves the post once; media lookups memoise per request. |
| Image dimensions | `resources/image-dimensions.php` | Generated by `php artisan images:manifest`, committed, so rendering never reads the filesystem. Keeps CLS at 0. |
| Responsive images | `MediaService::srcset()` | Uploaded images emit a real `srcset` (medium 640w + original). Static template assets have one rendition, so their markup is unchanged. |

Run `php artisan images:manifest --check` in CI after adding or replacing a
static asset; it fails when the committed manifest is out of date.

## Server-side (document, do not code into Laravel)

### Response compression

The application does **not** gzip responses. Compressing in PHP would duplicate
work a web server already does well and can double-compress. Configure it at
the web server or proxy:

**Nginx** (`/etc/nginx/nginx.conf`, `http` block):

```nginx
gzip on;
gzip_comp_level 5;
gzip_min_length 256;
gzip_proxied any;
gzip_vary on;
gzip_types
    text/plain text/css text/xml
    application/javascript application/json application/xml
    image/svg+xml font/woff2;

# Optional, if the stack supports it:
brotli on;
brotli_comp_level 5;
brotli_types text/plain text/css application/javascript application/json image/svg+xml;
```

**Apache** (`.htaccess` or vhost; requires `mod_deflate`):

```apache
<IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/plain text/css text/xml
    AddOutputFilterByType DEFLATE application/javascript application/json application/xml
    AddOutputFilterByType DEFLATE image/svg+xml
</IfModule>
```

Vite's build output is already minified; compression is the remaining win, and
it is the host's job.

### Nginx equivalent of the asset caching rules

If the deployment uses Nginx rather than Apache, `public/.htaccess` is ignored.
Add the equivalent:

```nginx
# Fingerprinted build output — safe to cache forever.
location ^~ /build/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    try_files $uri =404;
}

# Un-hashed template assets — cache, but revalidate.
location ^~ /assets/ {
    add_header Cache-Control "public, max-age=604800";
    try_files $uri =404;
}

# Uploaded media served from the storage symlink.
location ^~ /storage/ {
    add_header Cache-Control "public, max-age=604800";
    try_files $uri =404;
}
```

Do **not** add a `location /` cache rule that would make HTML documents
publicly cacheable: they carry a session and per-visitor flash state. The
application sends `private, no-cache, must-revalidate` with an `ETag`, which
is the correct policy for them.

### Optional: build step

`npm run build` must be run once when deploying (the output is committed to
`public/build/`, so a host without Node can still serve it). No Node runtime is
required at request time.

## Cache drivers

No Redis is required. `CACHE_STORE=database` (the default) or `file` both work
on shared hosting. The cache is used for public content and the sitemap; a
missing or unwritable cache store degrades to slower pages, never to an error.
